# ha_creator

Программа для проектирования умного дома под Home Assistant. Конвейер:

1. схема имеющихся коммуникаций объекта;
2. схема автоматизации (датчики, исполнители, сценарии);
3. подбор комплектующих, доступных в России, с ценами в рублях;
4. смета оборудования, материалов и работ;
5. экспорт готового проекта под Home Assistant (YAML, packages).

Эталонный объект — дача: на ней проверяется каждый этап.

## Состояние

Сделаны каркас проекта, модель данных, эталонная дача, каталоги v0, редактор цен, расчёт сметы
генератор конфигурации Home Assistant и схема имеющихся коммуникаций. Приложение работает
с эталонной дачей из `examples/dacha.json`.

## Схема коммуникаций

Раздел «Коммуникации» рисует воду, отопление, электрику и связь объекта в том виде, как они устроены сейчас.
Схема строится из описания объекта, а не рисуется вручную:

- **Зоны** — постройки и помещения. Неотапливаемые и неутеплённые рисуются пунктиром, у каждой может быть пометка
  («не отапливается · ~15 м от дома»).
- **Узлы** — оборудование: насос, гидроаккумулятор, котёл, водонагреватель, радиатор, щиток, роутер.
  У узла есть состояние: работает, выключен, слит, перекрыт.
- **Линии** — трубы и кабели. Цвет и штрих зависят от слоя и состояния; у линии бывают способ прокладки, глубина,
  утеплитель, греющий кабель (рисуется красным пунктиром рядом) и краны с положением «открыт/закрыт».
- **Слабые места** программа находит сама: водяное оборудование в холодном помещении, труба в земле выше глубины
  промерзания, труба снаружи, слитый водонагреватель без крана на подаче, одновременная остановка насоса, котла
  и греющего кабеля при отключении света. Узлы под угрозой подсвечиваются, при наведении на пункт подсвечивается
  его место на схеме.
- **«Проверьте, так ли это»** — утверждения, которые владелец подтверждает кнопками «Верно» / «Не так»
  с ответом. Ниже программа добавляет пробелы в данных, которые видит сама (не указана глубина, источник питания).

Узлы, зоны и подписи перетаскиваются мышью; при сдвиге узла изломы соседних линий двигаются вместе с ним.
Раскладка хранится в проекте (`diagram`) отдельно от описания, поэтому для нового объекта без раскладки она
строится автоматически. Правки сохраняются в браузере. «Скачать проект» выгружает JSON (его можно положить
вместо `examples/dacha.json`), «Открыть JSON» загружает проект, «Скачать SVG» — картинку схемы.

Добавлять узлы и линии мышью пока нельзя: состав схемы правится в JSON.

## Смета

Страница «Смета» считает проект по текущим ценам из редактора цен и выгружает результат в Excel.

- Каждая точка автоматизации с выбранным изделием — одна штука оборудования. Сервер, координатор, ИБП,
  кабель и прочее задаются в проекте списком `extras`.
- Монтаж точки берётся из расценки, у которой функция точки указана в `appliesTo`. Сопряжение Zigbee,
  сборка узлов ESPHome, настройка сценариев, установка HA, панель и пусконаладка добавляются автоматически.
  Остальные работы задаются списком `extraWorks`.
- Накладные: выезды, доставка и запас в процентах от оборудования, материалов и работ.
- Строки, посчитанные по непроверенным ценам, помечены, и показана их доля в сумме.

## Экспорт под Home Assistant

Страница «Экспорт HA» собирает архив: пакеты автоматизаций (`packages/`), панель (`dashboards/`),
строки для `configuration.yaml` и инструкцию с таблицей имён сущностей.

- На каждый сценарий проекта создаётся свой пакет. Параметры сценариев вынесены в помощники
  (`input_number` и другие): при первом запуске они получают значения из проекта, дальше меняются с панели.
- Автоматизации ссылаются на сущности по именам из проекта (`binary_sensor.leak_bathroom`). После сопряжения
  устройства его сущность нужно переименовать так, как указано в инструкции из архива.
- Действие для уведомлений задаётся при экспорте, по умолчанию `notify.notify`.
- Конфигурация дачи проверена командой `hass --script check_config` в Home Assistant 2026.2.3: ошибок нет.
  На живой установке с реальными устройствами она не запускалась.
- Прошивки ESPHome пока не генерируются.

То же из командной строки: `npm run export -- examples/dacha.json out`.

## Редактор цен

Открывается по `npm run dev`. В нём две вкладки: комплектующие и работы.

- Цена, статус и источник правятся прямо в таблице. Изменённая цена получает статус «проверено» и сегодняшнюю дату.
- Есть поиск, фильтр по категории и по состоянию: ориентир, проверено, старше 60 дней, изменено мной.
- **Импорт из Excel** принимает `.xlsx` и `.csv`. Колонки с артикулом, названием, ценой и источником определяются
  по заголовкам, и их можно поправить вручную. Позиции ищутся по артикулу, а если его нет — по точному названию.
  Перед применением показывается, какие цены изменятся; изменение больше чем в полтора раза помечается.
  Строки, которых нет в каталоге, не загружаются. Старый формат `.xls` не поддерживается.
- **Скачать Excel** выгружает текущую вкладку. Этот файл можно поправить в Excel и загрузить обратно.
- **Скачать YAML** выгружает каталог в формате репозитория: файл кладётся в папку `catalog` вместо прежнего.
- Правки хранятся в браузере (localStorage), сервера у приложения нет.

## Структура

| Путь | Что там |
| --- | --- |
| `packages/core` | Ядро без интерфейса: модель данных (Zod), проверка проекта, разбор прайс-листов, расчёт сметы, генератор конфигурации HA |
| `apps/web` | Веб-приложение (React + Vite): смета, редактор цен, экспорт под HA |
| `catalog/devices.yaml` | Каталог комплектующих |
| `catalog/works.yaml` | Справочник расценок на работы |
| `catalog/scenarios.yaml` | Каталог типовых сценариев автоматизации |
| `examples/dacha.json` | Эталонный проект дачи |

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm test          # тесты ядра
npm run typecheck # проверка типов
npm run dev       # веб-приложение на http://localhost:5173
```

## Что важно знать о данных

- **Цены в каталогах — ориентиры.** У каждой позиции стоит `priceStatus: estimate`: цены не сверены с магазинами.
  Перед расчётом настоящей сметы цену нужно проверить, указать `source`, обновить `priceDate`
  и поставить `priceStatus: verified`.
- **Коммуникации дачи взяты со схемы владельца:** дом с газовым котлом Vaillant turboTEC на антифризе, баня
  с гидроаккумулятором и щитком насоса, туалет бани, скважина с глубинным насосом, оптика и Keenetic Giga.
  Площади помещений, длины труб, мощность насоса и регион — оценка; пункты из блока «Проверьте, так ли это»
  владелец ещё не подтвердил. Точки автоматизации пока перенесены со старой версии и привязаны к новым
  помещениям: их нужно перепроектировать под газовый котёл и баню без Wi‑Fi.
- **Идентификаторы** (`id`) пишутся латиницей в нижнем регистре: из них будут строиться `entity_id` в Home Assistant.
